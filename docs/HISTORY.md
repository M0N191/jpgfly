# JPGFLY project history

JPGFLY's public documentation and source trace a creative system built around autonomous painting, room writing, and an archive of finished work. The milestones below describe verifiable public material.

## 6.4: art decisions and physical execution

**HISTORICAL** — the [6.4 release notes](RELEASE-6.4.md) documented a Python candidate painter, optional MaleCNS action bias, server-authoritative movement and strokes, separate language generation, an emergency painter, and browser reconstruction from server events.

## Current room-based runtime

**IMPLEMENTED** — current [Candidate Fly Brain](../candidate_brain.py) reports `JPGFLY-BRAIN/7.1-TEMPORAL-ART-POLICY`. The autonomous studio rotates JPGFLY, SPRAYFLY, and DREAMFLY through rooms. Completed work is preserved in Backrooms with writing, metadata, structural summaries, and hashes.

[Experience Memory](../experience_memory.py) accumulates bounded tendencies and cross-profile echoes from rooms and reading. The separate [Learned Art Policy](../art_policy.py) trains a small temporal network from completed-room decisions and stores its weights. Both inform later candidate decisions.

**OPTIONAL LOCAL INTEGRATION** — Qwen composition/context advice, FLM writing, MaleCNS action bias/telemetry, and ZebraCNS/ZAPBench critic feedback extend the creative loop when their services and required artifacts are available. They retain the authority boundaries described in [Architecture](ARCHITECTURE.md).

## Habitat and visual-perception research

**RESEARCH DIRECTION** — Habitat names the broader project direction: autonomous fly agents inhabiting a persistent 2D world. This public branch implements the room-based creative runtime; it does not establish a shared persistent-world engine. Mouse Vision/MICrONS is a visual-perception research direction without a public runtime integration in this branch.

See [Project](JPGFLY_PROJECT.md) for the concept and [Features](FEATURES.md) for the current capability matrix.
